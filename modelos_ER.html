1. Modelo Conceptual Global del Proyecto

Representa los objetos del mundo real y su funcionalidad en el ecosistema de ciberseguridad.

erDiagram USER ||--o{ SCAN : "ejecuta y solicita" SCAN ||--|| TARGET : "audita e inspecciona" SCAN ||--|| AI_ENGINE : "procesa mediante" SCAN ||--o{ REPORT : "genera documento" AI_ENGINE ||--o{ TELEMETRY : "analiza red y puertos" USER { string actor "Analista SOC / Administrador / Estudiante" string function "Gestiona credenciales, roles y auditorías" } TARGET { string object "Sitio Web, IP o Dominio objetivo" string function "Entidad del mundo real bajo inspección perimetral" } SCAN { string process "Auditoría activa de seguridad" string function "Calcula severidad y clasifica riesgos" } AI_ENGINE { string technology "DeBERTa-v3 INT8 (IA Local)" string function "Clasificación semántica y heurística de amenazas" } REPORT { string deliverable "Informe PDF Ejecutivo (Big Four)" string function "Presenta métricas, matrices 5x5 y planes de acción" } TELEMETRY { string data "Puertos TCP y Endpoints" string function "Evidencia técnica cruda del servidor" }
Explicación funcional: Un Usuario (Actor) introduce un Objetivo (Target) para ejecutar un Escaneo (Proceso). El sistema utiliza un Motor de IA para analizar la Telemetría obtenida y finalmente compilar un Informe (Entregable gerencial).

2. Modelo Entidad-Relación Físico (Base de Datos)

Estructura relacional que soporta el inicio de sesión, roles de administrador, registros e historiales.

erDiagram USER ||--o{ SCAN : "realiza" SCAN ||--o{ PORT_RESULT : "contiene" SCAN ||--o{ PATH_RESULT : "almacena" USER { int id PK "Identificador único" string username "Nombre de usuario (Login)" string email "Correo de contacto" string hashed_password "Contraseña cifrada (Seguridad)" boolean is_admin "Rol de Administrador / Permisos" datetime created_at "Fecha de registro" } SCAN { int id PK "Identificador del escaneo" string target "URL o IP auditada" string vulnerability_found "Diagnóstico global" string severity "Nivel (Bajo, Medio, Alto)" string inspection_type "Rápido o Profundo (IA)" json active_telemetry "Telemetría estructurada" datetime scanned_at "Marca de tiempo" int user_id FK "Usuario responsable" } PORT_RESULT { int id PK int scan_id FK "Relación con escaneo" int port_number "Puerto TCP (ej. 80, 443)" string state "Estado (Abierto/Cerrado)" string service_name "Servicio detectado" } PATH_RESULT { int id PK int scan_id FK "Relación con escaneo" string path_url "Ruta descubierta (ej. /admin)" int status_code "Código HTTP (200, 403)" string risk_level "Evaluación de riesgo" }
Explicación de la Base de Datos: La tabla User maneja la autenticación y los permisos de administrador. Cada usuario puede registrar múltiples Scan (historial). A su vez, cada escaneo se desglosa relacionalmente en tablas hijas como PortResult y PathResult para garantizar la normalización de la base de datos relacional.
